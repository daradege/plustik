# مستندات API بات سروش‌پلاس

## مقدمه

API بات یک رابط مبتنی بر HTTP است که برای توسعه‌دهندگانی که علاقه‌مند به ساخت بات برای سروش‌پلاس هستند طراحی شده است.

## ایجاد بات

هر بات هنگام ایجاد از طریق [splus.ir/botfather](https://splus.ir/botfather) یک توکن احراز هویت منحصر‌به‌فرد دریافت
می‌کند. توکن‌ها مشابه `123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11` است، اما در این سند فقط از `<token>` استفاده خواهد شد.

## ارسال درخواست

تمام درخواست‌ها به API بات سروش‌پلاس باید از طریق HTTPS با این شکل ارائه شوند:

```
https://api.splus.ir/bot<token>/METHOD_NAME
```

**مثال:**

```
https://api.splus.ir/bot123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11/getMe
```

ما از دو متد `GET` و `POST` و همچنین از چهار روش ارسال پارامتر در درخواست‌های API بات پشتیبانی می‌کنیم:

- **Url query string**
- **application/x-www-form-urlencoded**
- **application/json** (به جز بارگذاری فایل‌ها)
- **multipart/form-data** (استفاده در بارگذاری فایل‌ها)

### پاسخ‌ها

پاسخ شامل یک شیء JSON است که همیشه یک فیلد boolean به نام `ok` دارد و ممکن است یک فیلد رشته اختیاری به نام `description`
برای توضیح نتیجه درخواست داشته باشد. اگر `ok` برابر با `True` باشد، درخواست موفقیت‌آمیز بوده و نتیجه پرس‌وجو را می‌توان
در فیلد `result` یافت. در صورت ناموفق بودن، `ok` برابر با `False` است و خطا در `description` توضیح داده می‌شود. یک فیلد
عدد صحیح `error_code` نیز بازگردانده می‌شود، اما محتوای آن ممکن است در آینده تغییر کند. برخی خطاها ممکن است یک فیلد
اختیاری به نام `parameters` از نوع `ResponseParameters` داشته باشند که می‌تواند به مدیریت خودکار خطا کمک کند.

> **نکته:** هیچ حساسیتی نسبت به بزرگ یا کوچک بودن حروف در API بات سروش‌پلاس وجود ندارد. همه درخواست‌ها باید با فرمت
> UTF-8 ایجاد شوند.

## دریافت به‌روزرسانی‌ها

برای دریافت به‌روزرسانی‌های بات، دو روش مجزا وجود دارد: استفاده از `getUpdates` یا `webhooks`. به‌روزرسانی‌های ورودی تا
زمانی که بات آن‌ها را دریافت کند، روی سرور ذخیره می‌شوند؛ با این حال، این داده‌ها بیش از ۲۴ ساعت نگهداری نمی‌شوند.

فارغ از این‌که کدام روش را انتخاب کنید، در نهایت اشیای سریال‌شده‌ی `Update` را با فرمت JSON دریافت خواهید کرد.

### شیء Update

این شیء نشان‌دهنده‌ی یک به‌روزرسانی ورودی است. در هر به‌روزرسانی، حداکثر یکی از فیلدهای اختیاری می‌تواند وجود داشته
باشد.

| فیلد             | نوع                       | توضیحات                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
|------------------|---------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `update_id`      | Integer                   | شناسه‌ی منحصربه‌فرد به‌روزرسانی. شناسه‌های به‌روزرسانی از یک عدد مثبت مشخص شروع می‌شوند و به‌ترتیب افزایش می‌یابند. این شناسه به‌ویژه هنگام استفاده از webhooks کاربرد دارد، زیرا به شما امکان می‌دهد به‌روزرسانی‌های تکراری را نادیده بگیرید یا در صورت به‌هم‌خوردن ترتیب آن‌ها، توالی صحیح به‌روزرسانی‌ها را بازیابی کنید. اگر حداقل یک هفته هیچ به‌روزرسانی جدیدی دریافت نشود، شناسه‌ی به‌روزرسانی بعدی به‌صورت تصادفی انتخاب می‌شود و لزوماً ادامه‌ی توالی قبلی نخواهد بود. |
| `message`        | `Message` (اختیاری)       | پیام ورودی جدید از هر نوع، مانند متن، عکس، استیکر و غیره.                                                                                                                                                                                                                                                                                                                                                                                               |
| `edited_message` | `Message` (اختیاری)       | نسخه‌ی جدید پیامی که بات از آن مطلع است و ویرایش شده است. این به‌روزرسانی ممکن است در اثر تغییر فیلدهایی از پیام نیز ایجاد شود که در دسترس بات نیستند یا بات شما به‌طور مستقیم از آن‌ها استفاده نمی‌کند.                                                                                                                                                                                                                                                     |
| `callback_query` | `CallbackQuery` (اختیاری) | درخواست Callback جدید.                                                                                                                                                                                                                                                                                                                                                                                                                                  |

### متد getUpdates

از این متد برای دریافت به‌روزرسانی‌های ورودی با استفاده از Long Polling استفاده کنید. این متد آرایه‌ای از اشیای `Update`
را باز می‌گرداند.

| پارامتر           | نوع             | الزامی  | توضیحات                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
|-------------------|-----------------|---------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `offset`          | Integer         | اختیاری | شناسه‌ی اولین به‌روزرسانی‌ای که باید بازگردانده شود. این مقدار باید یک واحد بیشتر از بزرگ‌ترین `update_id` در میان به‌روزرسانی‌های دریافت‌شده‌ی قبلی باشد. به‌صورت پیش‌فرض، به‌روزرسانی‌ها از اولین مورد تأییدنشده بازگردانده می‌شوند. هر به‌روزرسانی زمانی تأییدشده محسوب می‌شود که `getUpdates` با مقدار `offset` بزرگ‌تر از `update_id` آن فراخوانی شود. همچنین می‌توانید از مقدار منفی برای `offset` استفاده کنید تا به‌روزرسانی‌ها از انتهای صف و از موقعیت `-offset` بازیابی شوند. در این حالت، تمام به‌روزرسانی‌های قبلی نادیده گرفته خواهند شد. |
| `limit`           | Integer         | اختیاری | حداکثر تعداد به‌روزرسانی‌هایی که باید بازیابی شوند. مقادیر بین ۱ تا ۱۰۰ پذیرفته می‌شوند و مقدار پیش‌فرض ۱۰۰ است.                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `timeout`         | Integer         | اختیاری | مدت‌زمان Timeout برای Long Polling، برحسب ثانیه. مقدار پیش‌فرض ۰ است که به‌معنای استفاده از Polling کوتاه معمولی است. برای Long Polling باید مقداری مثبت تعیین شود؛ Polling کوتاه فقط برای اهداف آزمایشی توصیه می‌شود.                                                                                                                                                                                                                                                                                                                 |
| `allowed_updates` | Array of String | اختیاری | فهرستی JSON-سریال‌شده از انواع به‌روزرسانی‌هایی که می‌خواهید بات دریافت کند. برای مثال، می‌توانید `["message", "edited_channel_post", "callback_query"]` را مشخص کنید تا فقط به‌روزرسانی‌های این نوع‌ها دریافت شوند. برای مشاهده‌ی فهرست کامل انواع موجود، به `Update` مراجعه کنید. برای دریافت همه‌ی انواع به‌روزرسانی به‌جز `chat_member`، `message_reaction` و `message_reaction_count`، یک فهرست خالی مشخص کنید؛ این رفتار پیش‌فرض است. اگر این پارامتر مشخص نشود، تنظیم قبلی حفظ خواهد شد.                                                 |

> **یادداشت‌ها:**  
> ۱. این روش اگر یک webhook خروجی راه‌اندازی شده باشد، کار نخواهد کرد.  
> ۲. برای جلوگیری از دریافت به‌روزرسانی‌های تکراری، پس از هر پاسخ سرور `offset` را دوباره محاسبه کنید.

### متد setWebhook

از این روش برای مشخص کردن یک URL و دریافت به‌روزرسانی‌های ورودی از طریق یک webhook خروجی استفاده کنید. هرگاه به‌روزرسانی
برای بات انجام شود، یک درخواست HTTPS POST به URL مشخص شده ارسال می‌کنیم که شامل یک `Update` JSON-serialized است. در صورت
ناموفق بودن درخواست (درخواستی با پاسخ HTTP کد وضعیت متفاوت از `2XY`)، درخواست را تکرار می‌کنیم و پس از تعداد معقولی تلاش
منصرف می‌شویم. `True` با موفقیت برمی‌گردد.

| پارامتر                | نوع             | الزامی  | توضیحات                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
|------------------------|-----------------|---------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `url`                  | String          | بله     | HTTPS URL برای ارسال به‌روزرسانی‌ها. از یک رشته خالی برای حذف ادغام وب‌هوک استفاده کنید.                                                                                                                                                                                                                                                                                                                                                                                 |
| `certificate`          | `InputFile`     | اختیاری | گواهی کلید عمومی خود را بارگذاری کنید تا گواهی ریشه در حال استفاده قابل بررسی باشد. برای جزئیات به راهنمای خودامضا مراجعه کنید.                                                                                                                                                                                                                                                                                                                                       |
| `ip_address`           | String          | اختیاری | آدرس IP ثابتی که برای ارسال درخواست‌های وب‌هوک استفاده می‌شود به جای آدرس IP که از طریق DNS حل می‌شود.                                                                                                                                                                                                                                                                                                                                                                    |
| `max_connections`      | Integer         | اختیاری | حداکثر تعداد مجاز اتصال HTTPS همزمان به وب‌هوک برای تحویل به‌روزرسانی، ۱ تا ۱۰۰. پیش‌فرض روی `40` است. از مقادیر پایین‌تر برای محدود کردن بار روی سرور بات خود استفاده کنید و مقادیر بالاتر را برای افزایش توان عملیاتی بات خود افزایش دهید.                                                                                                                                                                                                                              |
| `allowed_updates`      | Array of String | اختیاری | یک فهرست JSON-SERIALIZED شده از انواع به‌روزرسانی‌هایی که می‌خواهید بات شما دریافت کند. برای مثال، مشخص کنید `["message", "edited_channel_post", "callback_query"]` فقط به‌روزرسانی‌های این نوع‌ها را دریافت کند. برای فهرست کامل انواع به‌روزرسانی‌های موجود به `Update` مراجعه کنید. یک فهرست خالی برای دریافت همه انواع به‌روزرسانی به جز `chat_member`، `message_reaction` و `message_reaction_count` (پیش‌فرض) مشخص کنید. اگر مشخص نشده باشد، تنظیم قبلی استفاده خواهد شد. |
| `drop_pending_updates` | Boolean         | اختیاری | `True` را برای حذف تمام به‌روزرسانی‌های معلق ارسال کنید.                                                                                                                                                                                                                                                                                                                                                                                                                |

> **یادداشت‌ها:**  
> ۱. تا زمانی که وب‌هوک خروجی راه‌اندازی شده باشد، نمی‌توانید با استفاده از `getUpdates` به‌روزرسانی دریافت کنید.  
> ۲. برای استفاده از گواهی self-signed، باید گواهی کلید عمومی خود را با استفاده از پارامتر `certificate` بارگذاری کنید.
> لطفاً به‌صورت InputFile بارگذاری کنید، ارسال Sring کار نخواهد کرد.  
> ۳. پورت‌هایی که در حال حاضر پشتیبانی می‌شوند برای webhooks: ۴۴۳، ۸۰، ۸۸، ۸۴۴۳.

> اگر در راه‌اندازی وب‌هوک‌ها مشکلی دارید، لطفاً این راهنمای فوق‌العاده وب‌هوک‌ها را بررسی کنید.

**آدرس Webhook باید از طریق اینترنت و برای سرورهای سروش‌پلاس قابل دسترس باشد.** با این حال، توصیه می‌شود مسیر Webhook
به‌گونه‌ای انتخاب شود که به‌سادگی قابل حدس نباشد. برای مثال، می‌توانید از یک مقدار محرمانه و تصادفی یا توکن بات به‌عنوان
بخشی از مسیر Webhook استفاده کنید:

```
https://example.com/webhook/<BOT_TOKEN>
```

با این کار، احتمال ارسال درخواست‌های جعلی توسط اشخاصی که آدرس Webhook را نمی‌دانند کاهش پیدا می‌کند. توکن بات و آدرس
کامل Webhook را محرمانه نگه دارید و از انتشار آن‌ها در کدهای عمومی، لاگ‌ها یا مخازن عمومی خودداری کنید.

### متد deleteWebhook

از این روش برای حذف ادغام وب‌هوک استفاده کنید اگر تصمیم گرفتید به `getUpdates` برگردید. با موفقیت `True` را برمی‌گرداند.

| پارامتر                | نوع     | الزامی  | توضیحات                                                |
|------------------------|---------|---------|--------------------------------------------------------|
| `drop_pending_updates` | Boolean | اختیاری | `True` را برای حذف تمام به‌روزرسانی‌های معلق ارسال کنید. |

### متد getWebhookInfo

از این روش برای دریافت وضعیت فعلی webhook استفاده کنید. هیچ پارامتری نیاز ندارد. در صورت موفقیت، یک شیء `WebhookInfo`
برمی‌گردد. اگر بات از `getUpdates` استفاده کند، شیئی با فیلد `url` خالی برمی‌گرداند.

### شیء WebhookInfo

وضعیت فعلی یک وب‌هوک را توصیف می‌کند.

| فیلد                     | نوع                       | توضیحات                                                                                                                                                               |
|--------------------------|---------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `url`                    | String                    | آدرس وب‌هوک ممکن است خالی باشد اگر webhook تنظیم نشده باشد.                                                                                                            |
| `has_custom_certificate` | Boolean                   | `True` اگر گواهی سفارشی برای بررسی‌های گواهی وب‌هوک ارائه شده باشد.                                                                                                     |
| `pending_update_count`   | Integer                   | تعداد به‌روزرسانی‌های منتظر تحویل.                                                                                                                                      |
| `ip_address`             | String (اختیاری)          | آدرس IP وب‌هوک که در حال حاضر استفاده می‌شود.                                                                                                                           |
| `last_error_date`        | Integer (اختیاری)         | زمان یونیکس برای آخرین خطایی که هنگام تلاش برای ارائه به‌روزرسانی از طریق وب‌هوک رخ داد.                                                                                |
| `last_error_message`     | String (اختیاری)          | پیام خطا در قالب قابل‌خواندن انسانی برای آخرین خطایی که هنگام تلاش برای ارائه به‌روزرسانی از طریق وب‌هوک رخ داده است.                                                    |
| `max_connections`        | Integer (اختیاری)         | حداکثر تعداد مجاز اتصال HTTPS همزمان به وب‌هوک برای تحویل به‌روزرسانی.                                                                                                  |
| `allowed_updates`        | Array of String (اختیاری) | فهرستی از انواع به‌روزرسانی‌هایی که بات به آن‌ها مشترک است. به‌طور پیش‌فرض به همه نوع به‌روزرسانی‌ها به جز `chat_member`، `message_reaction` و `message_reaction_count` است. |

## انواع موجود

تمام انواع مورد استفاده در پاسخ‌های API بات به‌صورت شیء‌های JSON نمایش داده می‌شوند. استفاده از اعداد صحیح علامت‌دار ۳۲
بیتی برای ذخیره همه فیلدهای صحیح ایمن است مگر اینکه خلاف آن ذکر شده باشد.

> فیلدهای اختیاری در صورت نامربوط بودن ممکن است بازگردانده نشوند.

### شیء User

این شیء نمایانگر یک کاربر یا بات سروش‌پلاس است.

| فیلد                          | نوع               | توضیحات                                                                                                                                                                                                                                                                              |
|-------------------------------|-------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `id`                          | Integer           | شناسه یکتا برای این کاربر یا بات. این عدد ممکن است بیش از ۳۲ بیت مهم داشته باشد و برخی زبان‌های برنامه‌نویسی ممکن است در تفسیر آن دچار مشکل یا نقص‌های بی‌صدا شوند. اما حداکثر ۵۲ بیت معنادار دارد، بنابراین عدد صحیح ۶۴ بیتی یا نوع شناور با دقت دوبرابر برای ذخیره این شناسه ایمن است. |
| `is_bot`                      | Boolean           | `True` اگر این کاربر بات باشد.                                                                                                                                                                                                                                                       |
| `first_name`                  | String            | نام کوچک کاربر یا بات.                                                                                                                                                                                                                                                               |
| `last_name`                   | String (اختیاری)  | نام خانوادگی کاربر یا بات.                                                                                                                                                                                                                                                           |
| `username`                    | String (اختیاری)  | نام کاربری کاربر یا بات.                                                                                                                                                                                                                                                             |
| `language_code`               | String (اختیاری)  | تگ زبان IETF زبان کاربر.                                                                                                                                                                                                                                                             |
| `can_join_groups`             | Boolean (اختیاری) | `True`، اگر بات بتواند به گروه‌ها دعوت شود. فقط در `getMe` بازگردانده می‌شود.                                                                                                                                                                                                          |
| `can_read_all_group_messages` | Boolean (اختیاری) | `True`، اگر حالت حریم خصوصی برای بات غیرفعال شده باشد. فقط در `getMe` بازگردانده شده است.                                                                                                                                                                                            |
| `supports_inline_queries`     | Boolean (اختیاری) | `True`، اگر بات از کوئری‌های inline پشتیبانی کند. فقط در `getMe` بازگردانده شده است.                                                                                                                                                                                                  |

### شیء Chat

این شیء نمایانگر یک چت است.

| فیلد                             | نوع                         | توضیحات                                                                                                                                                                                                                                                                                                                                                                 |

### شیء CallbackQuery

این شیء نمایانگر یک پرس و جوی فراخوانی ورودی از یک دکمه فراخوانی در یک صفحه‌کلید inline است. اگر دکمه‌ای که پرس‌وجوی را

بات ارسال شده باشد (در حالت inline)، `inline_message_id` فیلد حضور خواهد داشت. دقیقاً یکی از فیلدهای `data` یا

| فیلد      | نوع                                  | توضیحات                                                                                                                   |
|-----------|--------------------------------------|---------------------------------------------------------------------------------------------------------------------------|
| `id`      | String                               | شناسه یکتا برای این پرس‌وجو.                                                                                               |
| `from`    | `User`                               | فرستنده.                                                                                                                  |
| `message` | `MaybeInaccessibleMessage` (اختیاری) | پیامی که توسط بات با دکمه تماس برگشتی ارسال شده و پرسش را آغاز کرده است.                                                  |
| `data`    | String (اختیاری)                     | داده‌های مرتبط با دکمه callback. توجه داشته باشید که پیام منشأ پرس‌وجو نمی‌تواند هیچ دکمه فراخوانی با این داده‌ها داشته باشد. |

> **توجه:** پس از آنکه کاربر دکمه Callback را فشار می‌دهد، کلاینت‌های سروش‌پلاس نوار پیشرفت را نمایش می‌دهند تا زمانی که
> شما درخواست `answerCallbackQuery` بدهید. بنابراین، لازم است حتی اگر نیازی به اطلاع‌رسانی به کاربر نباشد (مثلاً بدون مشخص
> کردن هیچ یک از پارامترهای اختیاری) با `answerCallbackQuery` واکنش نشان دهید.

### شیء ForceReply

پس از دریافت پیامی با این شیء، کلاینت‌های سروش‌پلاس یک رابط پاسخ به کاربر نمایش می‌دهند (طوری رفتار می‌کنند که گویی
کاربر پیام بات را انتخاب کرده و روی «پاسخ» ضربه زده است). این می‌تواند بسیار مفید باشد اگر بخواهید رابط‌های گام به گام
کاربرپسند ایجاد کنید بدون اینکه مجبور باشید حالت حریم خصوصی را قربانی کنید. **در کانال‌ها و برای پیام‌هایی که به
نمایندگی از حساب کاربری ارسال می‌شوند، پشتیبانی نمی‌شود.**

| فیلد                      | نوع               | توضیحات                                                                                                                                                                                                                               |
|---------------------------|-------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `force_reply`             | Boolean           | رابط پاسخ را به کاربر نشان می‌دهد، انگار که او به‌صورت دستی پیام بات را انتخاب کرده و روی «پاسخ» ضربه زده است.                                                                                                                          |
| `input_field_placeholder` | String (اختیاری)  | موقتی که در فیلد ورودی هنگام فعال بودن پاسخ نمایش داده می‌شود؛ ۱ تا ۶۴ کاراکتر.                                                                                                                                                        |
| `selective`               | Boolean (اختیاری) | اگر می‌خواهید پاسخ را فقط از کاربران خاص اجباری کنید، از این پارامتر استفاده کنید. اهداف: ۱) کاربرانی که در `text` شیء `Message` @mentioned هستند؛ ۲) اگر پیام بات پاسخ به پیامی در همان موضوع چت و انجمن باشد، فرستنده پیام اصلی است. |

> **مثال:** یک بات نظرسنجی برای گروه‌ها در حالت حریم خصوصی اجرا می‌شود (فقط دستورات را دریافت می‌کند، به پیام‌ها و
> اشاره‌ها پاسخ می‌دهد). دو روش برای ایجاد نظرسنجی جدید می‌تواند وجود داشته باشد... گزینه آخر قطعا جذاب‌تر است. و اگر
> `ForceReply` را در سوالات بات خود استفاده کنید، پاسخ‌های کاربر را دریافت می‌کند حتی اگر فقط پاسخ‌ها، فرمان‌ها و اشاره‌ها
> را دریافت کند - بدون زحمت اضافی برای کاربر.

## روش‌های موجود

تمام متدهای API بات حساس به حروف بزرگ نیستند. ما از متدهای GET و POST پشتیبانی می‌کنیم. برای عبور پارامترها در
درخواست‌های API بات از رشته جستجوی URL یا `application/json` یا `application/x-www-form-urlencoded` یا
`multipart/form-data` استفاده کنید.

در صورت فراخوانی موفق، یک شیء JSON که شامل نتیجه باشد بازگردانده می‌شود.

### getMe

یک روش ساده برای آزمایش توکن احراز هویت بات شما. هیچ پارامتری نیاز ندارد. اطلاعات پایه درباره بات را به‌صورت یک شیء
`User` بازمی‌گرداند.

### logOut

از این روش برای خروج از سرور API بات ابری قبل از راه‌اندازی بات به‌صورت محلی استفاده کنید. قبل از اجرای محلی باید بات را
خارج کنید، در غیر این صورت تضمینی وجود ندارد که بات به‌روزرسانی دریافت کند. پس از تماس موفق، می‌توانید بلافاصله روی سرور
محلی وارد شوید، اما تا ۱۰ دقیقه نمی‌توانید دوباره وارد سرور API بات ابری شوید. `True` را پس از موفقیت برمی‌گرداند. نیازی
به پارامترها ندارد.

### close

از این روش برای بستن نمونه بات قبل از انتقال آن از یک سرور محلی به سرور دیگر استفاده کنید. قبل از فراخوانی این متد باید
webhook را حذف کنید تا مطمئن شوید بات پس از راه‌اندازی مجدد سرور دوباره اجرا نمی‌شود. این روش در ۱۰ دقیقه اول پس از
راه‌اندازی بات خطای ۴۲۹ را بازمی‌گرداند. `True` را هنگام موفقیت برمی‌گرداند. نیازی به پارامترها ندارد.

### sendMessage

از این روش برای ارسال پیامک استفاده کنید. در صورت موفقیت، `Message` ارسال شده بازگردانده می‌شود.

| پارامتر                       | نوع                                                                                      | الزامی  | توضیحات                                                                                                                                       |
|-------------------------------|------------------------------------------------------------------------------------------|---------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| `chat_id`                     | Integer or String                                                                        | بله     | شناسه منحصر به فرد برای چت هدف یا نام کاربری در قالب `@username`.                                                                             |
| `text`                        | String                                                                                   | بله     | متن پیام ارسالی، 1-4096 کاراکتر پس از Entities Parsing.                                                                                       |
| `parse_mode`                  | String                                                                                   | اختیاری | حالت برای Entities Parsing در متن پیام.                                                                                                       |
| `entities`                    | Array of `MessageEntity`                                                                 | اختیاری | فهرستی JSON-SERIALIZED شده از موجودیت‌های ویژه که در متن پیام ظاهر می‌شوند و می‌توان آن‌ها را به جای `parse_mode` مشخص کرد.                       |
| `reply_markup`                | `InlineKeyboardMarkup` or `ReplyKeyboardMarkup` or `ReplyKeyboardRemove` or `ForceReply` | اختیاری | گزینه‌های رابط کاربری اضافی. یک شیء سریال‌سازی شده JSON برای صفحه‌کلید inline، ReplyMarkup، دستورالعمل حذف صفحه‌کلید پاسخ یا اجبار پاسخ از کاربر. |
| `disable_web_page_preview`    | Boolean                                                                                  | اختیاری | پیش‌نمایش لینک‌ها در این پیام را غیرفعال می‌کند.                                                                                                 |
| `reply_to_message_id`         | Integer                                                                                  | اختیاری | اگر پیام پاسخ باشد، شناسه پیام اصلی.                                                                                                          |
| `allow_sending_without_reply` | Boolean                                                                                  | اختیاری | `True` اگر پیام حتی در صورت پیدا نشدن پیام پاسخ‌داده‌شده ارسال شود.                                                                             |

### گزینه‌های قالب‌بندی

API بات از قالب‌بندی پایه برای پیام‌ها پشتیبانی می‌کند. می‌توانید از بولد، ایتالیک، زیرخط دار، خط خورده‌ای و متن اسپویلر
کدهای از پیش فرمت‌شده در پیام‌های بات‌های خود استفاده کنید. کلاینت‌های سروش‌پلاس آن‌ها را متناسب با آن رندر خواهند کرد.
می‌توانید موجودیت‌های متنی را مستقیماً مشخص کنید یا از قالب‌بندی به سبک مارک‌داون یا HTML استفاده کنید.

توجه داشته باشید که کلاینت‌های سروش‌پلاس قبل از باز کردن لینک inline («این لینک را باز کنید؟» همراه با آدرس کامل URL)
هشدار به کاربر نمایش می‌دهند.

**موجودیت‌های پیام می‌توانند تو در تو باشند، به شرطی که محدودیت‌های زیر رعایت شوند:**

- اگر دو موجودیت کاراکتر مشترک داشته باشند، یکی از آن‌ها کاملاً درون دیگری قرار دارد.
- `bold`، `italic`، `underline`، `strikethrough` و `spoiler` موجودیت می‌توانند شامل و بخشی از هر موجودیت دیگری باشند، به
  جز `pre` و `code`.
- همه موجودات دیگر نمی‌توانند یکدیگر را نگه دارند.

می‌توانید فهرست زبان‌های برنامه‌نویسی و نشانه‌گذاری که برجسته‌سازی نحو آن‌ها پشتیبانی می‌شود را در
libprisma#supported-languages پیدا کنید.

#### قالب‌بندی موجودیت تاریخ-زمان

قالب‌بندی موجودیت تاریخ-زمان توسط یک رشته قالب مشخص می‌شود که باید به عبارت منظم `r|w?[dD]?[tT]?` پایبند باشد. اگر رشته
فرمت خالی باشد، متن زیرین همان طور که هست نمایش داده می‌شود؛ با این حال، کاربر همچنان می‌تواند تاریخ زیرین را در قالب
محلی خود دریافت کند. وقتی پر شود، رشته فرمت خروجی را بر اساس وجود کاراکترهای کنترلی زیر تعیین می‌کند:

- `r`: زمان را نسبت به زمان فعلی نمایش می‌دهد. نمی‌توان آن را با هیچ کاراکتر کنترلی دیگری ترکیب کرد.
- `w`: روز هفته را به زبان بومی شده کاربر نمایش می‌دهد.
- `d`: تاریخ را به‌صورت کوتاه نمایش می‌دهد (مثلاً «17.03.22»).
- `D`: تاریخ را به‌صورت طولانی نمایش می‌دهد (مثلاً «۱۷ مارس ۲۰۲۲»).
- `t`: زمان را به‌صورت کوتاه نمایش می‌دهد (مثلاً «۲۲:۴۵»).
- `T`: زمان را به‌صورت طولانی نمایش می‌دهد (مثلاً «۲۲:۴۵:۰۰»).

- برای مشخص‌کردن زبان برنامه‌نویسی در یک موجودیت pre، از تگ‌های `pre` و `code` به‌صورت تو‌در‌تو استفاده کنید.
- برای تگ مستقل `code` نمی‌توان زبان برنامه‌نویسی مشخص کرد.

## به‌روزرسانی پیام‌ها

روش‌های زیر به شما اجازه می‌دهند پیام موجود در تاریخچه پیام را تغییر دهید به جای اینکه پیام جدیدی با نتیجه یک اقدام ارسال کنید. این روش بیشتر برای پیام‌هایی با صفحه‌کلید inline و استفاده از درخواست‌های callback مفید است، اما همچنین می‌تواند به کاهش شلوغی گفتگوها با بات‌های چت معمولی کمک کند.

لطفاً توجه داشته باشید که در حال حاضر فقط امکان ویرایش پیام‌ها بدون `reply_markup` یا با کیبوردهای inline وجود دارد.

از این روش برای ویرایش پیام‌های متنی استفاده کنید. در صورت موفقیت، اگر پیام ویرایش شده پیام inline نباشد، `Message` ویرایش شده بازگردانده می‌شود، در غیر این صورت `True` بازگردانده می‌شود.

|---------|-----|--------|---------|

| `text` | String | بله | متن جدید پیام، 1-4096 کاراکتر پس از تجزیه موجودیت. |
| `parse_mode` | String | اختیاری | حالت برای Entities Parsing در متن پیام. |
| `entities` | Array of `MessageEntity` | اختیاری | فهرستی JSON-SERIALIZED شده از special entities که در متن پیام ظاهر می‌شوند. |
| `reply_markup` | `InlineKeyboardMarkup` | اختیاری | یک شیء JSON-SERIALIZED شده برای inline keyboard. |
| `disable_web_page_preview` | Boolean | اختیاری | پیش‌نمایش لینک‌ها در این پیام را غیرفعال می‌کند. |

### editMessageCaption

از این روش برای ویرایش کپشن پیام‌ها استفاده کنید. در صورت موفقیت، اگر پیام ویرایش شده پیام inline نباشد، `Message` ویرایش شده بازگردانده می‌شود، در غیر این صورت `True` بازگردانده می‌شود.

| پارامتر | نوع | الزامی | توضیحات |

| `message_id` | Integer | اختیاری | اگر مشخص نشده `inline_message_id` الزامی است. شناسه پیام برای ویرایش. |
| `caption` | String | اختیاری | کپشن جدید پیام، ۰ تا ۱۰۲۴ کاراکتر پس از Entities Parsing. |

| `reply_markup` | `InlineKeyboardMarkup` | اختیاری | یک شیء JSON-SERIALIZED شده برای inline keyboard. |

### editMessageMedia

### editMessageReplyMarkup

## استیکرها

روش‌ها و اشیای زیر به بات شما اجازه می‌دهد استیکرها و مجموعه‌های استیکر را مدیریت کند.

### شیء Sticker

این شیء نمایانگر یک استیکر است.

| فیلد | نوع | توضیحات |
|------|-----|---------|
| `file_id` | String | شناسه این فایل که می‌تواند برای دانلود یا استفاده مجدد از فایل استفاده شود. |
| `file_unique_id` | String | شناسه یکتا برای این فایل که قرار است در طول زمان و برای بات‌های مختلف یکسان باشد. نمی‌توان از آن برای دانلود یا استفاده مجدد فایل استفاده کرد. |
| `width` | Integer | عرض استیکر. |
| `height` | Integer | ارتفاع استیکر. |
| `is_animated` | Boolean | `True` اگر استیکر انیمیشن باشد. |
| `is_video` | Boolean | `True` اگر استیکر یک استیکر ویدئویی باشد. |
| `thumb` | `PhotoSize` (اختیاری) | تصویر کوچک استیکر در قالب .WEBP یا .JPG. |
| `emoji` | String (اختیاری) | ایموجی مرتبط با استیکر. |
| `set_name` | String (اختیاری) | نام مجموعه استیکر که استیکر به آن تعلق دارد. |
| `mask_position` | `MaskPosition` (اختیاری) | برای استیکرهای ماسک، محل قرار دادن ماسک. |
| `file_size` | Integer (اختیاری) | اندازه فایل بر حسب بایت. |

### شیء StickerSet

این شیء نمایانگر یک مجموعه استیکر است.

| فیلد | نوع | توضیحات |
|------|-----|---------|
| `name` | String | نام مجموعه استیکر. |
| `title` | String | عنوان مجموعه استیکر. |
| `stickers` | Array of `Sticker` | فهرست تمام استیکرهای مجموعه. |
| `thumb` | `PhotoSize` (اختیاری) | تصویر Thumbnail مجموعه استیکر در .وب، .TGS، یا .WEBM. |

### شیء MaskPosition

این شیء موقعیت روی سطوح را توصیف می‌کند که ماسک باید به‌طور پیش‌فرض در آن قرار گیرد.

| فیلد | نوع | توضیحات |
|------|-----|---------|
| `point` | String | بخشی از صورت که ماسک باید نسبت به آن قرار گیرد. یکی از «forehead»، «eyes»، «mouth» یا «chin». |
| `x_shift` | Float | شیفت با محوری X که به عرض ماسک مقیاس شده بر اساس اندازه صورت، از چپ به راست اندازه‌گیری می‌شود. |
| `y_shift` | Float | شیفت توسط محور Y که بر حسب ارتفاع ماسک مقیاس شده بر اساس اندازه صورت، از بالا به پایین اندازه‌گیری می‌شود. |
| `scale` | Float | ضریب مقیاس‌پذیری ماسک. |

### sendSticker

از این روش برای ارسال استاتیک .WEBP، انیمیشنی .TGS یا ویدیو .WEBM استیکرها استفاده کنید. پس از موفقیت، `Message` ارسال شده بازگردانده می‌شود.

| پارامتر | نوع | الزامی | توضیحات |
|---------|-----|--------|---------|
| `chat_id` | Integer or String | بله | شناسه منحصر به فرد برای چت هدف (قالب `@username`). |
| `sticker` | `InputFile` or String | بله | استیکر برای ارسال. یک `file_id` به‌صورت رشته ارسال کنید تا فایلی که روی سرورهای سروش‌پلاس وجود دارد ارسال شود (توصیه می‌شود)، یک آدرس HTTP را به‌صورت رشته برای سروش‌پلاس ارسال کنید تا استیکر .WEBP از اینترنت دریافت کند، یا یک استیکر جدید .WEBP، .TGS یا .WEBM با استفاده از داده‌های multipart/form-data آپلود شود. استیکرهای ویدیویی و متحرک را نمی‌توان از طریق آدرس HTTP ارسال کرد. |
| `reply_markup` | ... | اختیاری | گزینه‌های رابط کاربری اضافی. |
